# Tests

## Test Strategy

- Unitaires (`pnpm test`) : domaine et contrats, sans base. 442 tests.
- Intégration (`pnpm test:integration`) : l'app entière en mémoire (`app.request()`), sur une vraie PostgreSQL, un fichier par comportement d'ADR. 510 tests.
- Mutation (`pnpm --filter @repo/api mutation`, Stryker en place, en local seulement) : mesure la force des tests ; seuils 90 / 100 %, sans blocage. `--mutate <fichiers>` restreint le run aux fichiers touchés.
- Bench (`pnpm bench`) : `apps/api/bench/*.bench.ts`, sur une vraie PostgreSQL ; voir [PERFORMANCE.md](PERFORMANCE.md).
- Vert = les deux suites en CI (`ci.yml`).

## Characterization Backlog

- [x] Mesurer le score de mutation du module identity : 97,2 % (395 mutants), ce qui termine la mesure par module de [#108](https://github.com/Muhammed21/dezyn/issues/108). Les 10 survivants tuables sont tués : la rotation de la clé de signature (expiration à 90 jours, un jour de grâce dans le JWKS), le titre des trois pages, la page de connexion vide, le corps du 403 de consentement, un jeton de formulaire envoyé comme fichier, une redirection locale enfermée dans un tableau. Les 11 autres sont équivalents : la garde `typeof` d'`isRecord` (un corps qui n'est pas un objet n'a ni type ni redirection), le test du chemin `/oauth2/register` du hook (les autres corps n'ont pas de redirection et repartent tels quels), les colonnes du `select` de `postgres-active-grants`, le repli `""` d'un champ absent, le repli d'un cookie CSRF absent (seul un formulaire qui enverrait la valeur du mutant passerait), `append: true` des cookies (la connexion n'en pose qu'un, `better-auth.session_token`), l'en-tête `accept` (better-auth répond en JSON), le corps `null` d'un GET (`JSON.stringify(undefined)` vaut aussi rien), le repli du `client_id` absent (un client inconnu reçoit déjà la page d'expiration), le repli de `markup` (inatteignable)
- [x] Mesurer le score de mutation du module proposal : 97,5 % (794 mutants). Deux tests de concurrence tuent les 5 survivants tuables : une proposition remplacée pendant la validation de son lot reste Remplacée (statut relu sous verrou), et deux premières écritures simultanées de la même IA vont dans le même lot (`openBatchOf` rend le lot déjà ouvert). Les 20 autres sont équivalents : le code `not_found` de `listBatches` et `batchOf` (la route ne le lit pas), les gardes `found === undefined` et `batch === undefined` (l'espace est alors déjà absent), le `?.` du statut verrouillé (le verrou rend toutes les propositions du lot), les codes `invalid_proposition` et `unchecked_tokens` (les appelants ne testent que l'autre code), la clé du verrou consultatif et la portée du `for update` de `pendingOf` (un verrou plus large sérialise les mêmes écritures), le message, le `?.` et le test `instanceof` de `RolledBack` (une erreur inattendue rend 500 dans tous les cas), la garde d'UUID de `review-routes` (un identifiant absent ne correspond à aucune ligne, la route rend déjà 404)
- [x] Mesurer le score de mutation du module space : 97,3 % (664 mutants). Le seul survivant tuable, le `type` du problème 503 d'un email d'invitation non envoyé, est tué. Les 18 autres sont équivalents : la garde `membership === undefined` de `leave-space` et `read-space` (`can` refuse déjà une adhésion absente et tous les rôles peuvent lire et partir), la garde `largest === undefined` de `storage-warning` (sans projet, 0 octet n'atteint jamais l'alerte), les colonnes des `select` qui verrouillent l'espace ou comptent des lignes dans `postgres-departures`, `postgres-member-management`, `postgres-invitation-acceptance` et `postgres-member-directory`, la garde d'UUID de `spaces-routes` (un identifiant absent ne correspond à aucune ligne, la route rend déjà 404)
- [x] Mesurer le score de mutation du module history : 95,9 % (171 mutants). Les 7 survivants sont équivalents : le `catch` de `parseJson` et la garde `last !== undefined` de `history-cursor` et `read-history`, le code du `not_found` de `readHistory` (la route ne le lit pas et l'outil refuse un projet inconnu avant), le `false` d'un historique indisponible dans `record-project-call`, le `code` de l'issue « Curseur invalide » (problem+json ne rend que le chemin et le message), la garde d'UUID de `history-routes` (l'accès rend déjà 404)

## CI Gates

- `ci.yml` : `pnpm test` et `pnpm test:integration` bloquent le merge.
- Stryker tourne en local seulement : sur un diff de 10 fichiers, le run dépasse 60 min en CI, même sans les mutants statiques.
- `perf-pr.yml` et `perf-main.yml` comparent les benchs à la référence de `main`, à titre informatif, sans jamais bloquer ; un bench sans échantillon fait échouer le job.
